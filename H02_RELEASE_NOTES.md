# H02 — fidelity-first + experimental pixel-scroll pass

Baseline: H01 frozen (unaltered). All banks 1–19 are generated by the unchanged
original conversion pipeline and should match H01 byte-for-byte.

## Gameplay correctness vs H01

- **Kraken entry**: clear all 40 enemy records with zero before the arena starts.
  H01 accidentally replicated `05h` from its high timer byte into every enemy
  record (active phantom entities).
- **Respawn in stages 2–6**: use the stage-specific START_X/Y from the original
  stage header instead of the phase-1 mothership intro coordinates.
- Keep tick order, enemy formation schedule, authored hits/hitboxes, player
  acceleration, original stage graphics, palette and audio data unchanged.

## Experimental smooth scrolling

SOURCE supports two reproducible builds:

```
SMOOTH_SCROLL=1 ./build.sh  # pixel-scroll evaluation build (default)
SMOOTH_SCROLL=0 ./build.sh  # conservative H02 build, original tile presentation
```

With the evaluation build, `SCROLL_SUB` drives VDP scrolling every game tick
instead of updating the visible scenery only at tile changes:

- V9938 / MSX2: horizontal display adjustment R#18, 0..7 pixels left.
  Known **visual compromises**: this moves display borders and HUD, potentially
  affecting sprite alignment. This is NOT a finished production scrolling engine.
- V9958 / MSX2+ / turboR: hardware scroll R#26+27, coarse/fine compensating
  every 8-pixel scene redraw; R#25 is left in single-page, unmasked mode.
  Known **visual compromises**: border at the extreme left and tiles wrapping
  at extreme right; the full-screen HUD is subject to the scroll. A raster
  split, right-edge buffering or other per-zone render strategy is needed for
  production fidelity. No claims of flawless scrolling until visual QA.

The sprite and gameplay update cadence remains 33.3 logical ticks/s, same as H01.
Faster hardware DOES NOT change game speed. The pixel camera interpolates
screen positions inside each already-existing 8-pixel tile interval.

## Honest QA scope

- Native assembler builds both motors independently from SOURCE (no binary patch).
- `validate_hybrid.py`: 85 static validation checks.
- `test_h02.py`: bank shape, scroll maths, fixed regressions, source invariants.
- Rebuild hash stability and source asset-bank identity versus frozen H01 should
  be checked in each release.
- The emulator/hardware scroll appearance and full stages 2..6 remain pending.
  H02 is **not** declared a faithful definitive port yet.
